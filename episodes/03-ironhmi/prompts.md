# CNC HMI 초안 작업 프롬프트 모음

> 데모 CNC 장비의 IronHMI 조작 화면(`src/HMI_Vertical`, `src/HMI_Horizontal`) 초안을 AI와 만들 때 쓴 프롬프트를 정리한 것입니다.
> 순서는 **설계 → 구현 계획 → 작업 → 마무리**입니다. 경로·주소는 자기 환경에 맞게 바꿔 쓰세요(`<...>` 자리).
> 당시에는 세로판·가로판 두 벌을 만들었고, 이 저장소에는 영상에서 쓴 가로판만 `src/HMI` 로 들어 있습니다. 프롬프트는 쓴 그대로 두었으므로 프롬프트 안의 `src/HMI_Horizontal` 은 지금의 `src/HMI`, `IO\IO` 는 `Cnc/OpMode`, `AxisMgr` 는 `Motion/AxisManual` 입니다.

## 0. 공통 규칙 (첫 메시지에 한 번)

```text
데모 CNC 장비의 조작 화면(HMI)을 만든다. 아래 규칙은 이 대화 내내 지켜라.

[대상]
- 장비: 3축 X/Y/Z 직교 갠트리 디스펜서(B&R X20CP1684, mapp Motion MpCnc3Axis). 나중에 레이저 등에도 쓰는 범용 CNC HMI로 키운다.
- PLC 레포: <저장소 경로> (src/PLC). HMI는 같은 레포 src/ 아래에 만든다.
- 런타임: IronHMI(<IronHMI 설치 경로>), 검증 도구: <IronStudio 설치 경로>\bin\ironhmi-cli.exe
- PLC 접속: OPC UA opc.tcp://<PLC 주소>:4840 (namespaceIndex는 첫 접속에서 확정)

[보고 방식]
- 쉽고 짧게. 한 줄 요약 → 묶음 → 항목마다 쉬운 말 한 줄. 긴 표·규격 번호 나열 금지.
- 디자인 의견은 반드시 목업(실제 해상도 PNG)으로 보여 주고, 대안은 3개.
- 오래 걸리는 작업은 시작할 때 예상 시간을 말하고, 중간에 진행 상황을 짧게 알려라.

[허가]
- 커밋은 해도 되지만 메시지 맨 앞에 [초안]을 붙이고, 무엇을 왜 했는지 한글로 쓴다.
- push, PR 생성·수정, 머지, 브랜치 삭제는 내가 "해"라고 말할 때만 한다. 준비가 끝났다는 내 말은 허가가 아니다.
- 문서 파일·새 브랜치도 내가 만들라고 할 때만 만든다.

[가정 금지]
- 실행 PC 사양(32/64비트, 성능)을 짐작해서 디자인을 깎지 마라.
- 장비 구성(핸드휠, 센서, 배선 등)이 불확실하면 PLC 소스로 확인하고, 그래도 모르면 물어라.
- PLC에 없는 값은 화면에 있는 척 그리지 마라. 없으면 '미지원'으로 보여 주고 이유를 단다.
```

## 1단계. 설계

### 1-1. CNC HMI 요소 정리

```text
범용 CNC HMI(3축 직교로봇 — 디스펜서·레이저 등)에 있어야 할 요소와 좋은 UI를 조사해서 정리해라. 작업은 하지 말고 정리만 한다.

- 운전자가 화면에서 "하는 일" 기준으로 5개 안팎으로 묶어라(예: 상태 보기, 운전, 수동 조작, 프로그램, 설정, 기록).
- 묶음마다 항목 3~6개를 "쉬운 말 한 줄 + 지금 우리 PLC에 있음/반쪽/없음"으로 적어라.
- 이미 정한 것:
  · 핸드휠은 있다. 다만 조작자가 장비를 직접 보며 돌리므로 화면에는 축·배율 대신 "핸드휠 사용 중/아님" 정도만 표시.
  · 문 신호는 제외, 설정 백업/복원은 이미 있으니 제외, 출력 강제·정비 카운터 예보는 제외.
  · 언어 전환은 남기되 "우선도 낮음, 필요할 때 작업"이라는 작성자 의견을 붙임.
  · 백래시·서보 튜닝은 PLC 영역이라는 의견을 붙임.
  · 헤드 2개 동시 장착은 바뀔 수 있으니 보류. "구성설정에서 어떤 헤드를 쓸지 고르는 방식"을 의견으로 붙임.
- 결과는 위젯처럼 한눈에 들어오게 보여 주고, 문서 상단에 작성일과 작성자를 넣는다. 형식(HTML 등)은 먼저 추천만 하고 내가 정하면 만든다.
```

### 1-2. 디자인 방향 (벤치마크)

```text
화면 디자인 벤치마크는 <참고할 장비의 세로 터치 화면>이다. 첨부 사진을 기준으로 삼아라.

벤치마크에서 가져올 것:
- 화면 전체를 정사각형 타일 모자이크로 채운다(1x1·2x1·2x2, 좁은 틈). 흰 카드 나열이 아니다.
- 단일 색조 강철 파랑 타일 + 큰 흰 선 아이콘 + 한두 단어 라벨.
- 가운데 큰 3D 공작물 뷰(밝은 무대)를 타일들이 감싼다.
- 숫자는 적게, 크게(진행률, 남은 시간처럼 핵심만).
- 심심함은 큰 색 면적과 아이콘 리듬, 타일 질서로 푼다. 차트·글로우·다크 관제실 스타일로 풀지 마라.

조건:
- 터치 패널 조작: 운전 명령 타일은 크게, 최소 터치 대상 약 166x162, 캡션 최소 14px, 2 m 거리에서 운전 상태·진행·남은 시간이 읽혀야 한다.
- 정지는 일시정지와 붙이지 말고 크게, 빨강. "비상정지"라고 쓰지 마라(HMI 정지는 프로그램 정지다).
- 실행 중 바꾸면 위험한 것(토출 모드, 파일 선택, HOME 등)은 잠그고 자물쇠 + 이유 한 줄.
- 엔진 3D 뷰포트 오른쪽 위 120px은 엔진의 뷰 큐브·카메라 버튼 자리이니 비워 둔다.

대안 3개를 1080x1920 목업(HTML → 헤드리스 Chrome으로 PNG)으로 만들고 벤치마크 사진과 나란히 비교해서 보고해라.
```

### 1-3. 화면 틀과 네비

```text
화면 틀은 세로판과 가로판 두 벌이다. 폴더 이름은 처음부터 뜻에 맞게 짓는다.
- 세로판(1080x1920): src/HMI_Vertical
- 가로판(1920x1080): src/HMI_Horizontal

네비(5개 탭: 작업현황 · I/O 확인 · 구성설정 · 작업기록 · 작업이력)
- 공통 모양은 "세그먼트 트랙": 회색 트랙 안에 칸을 나누고, 선택 칸만 흰 알약으로 뜨고, 누르면 살짝 줄어드는 효과. hover 효과 없음.
- 세로판: 위쪽 헤더(로고·운전 상태·시계·알람·로그인) 아래에 가로 트랙.
- 가로판: 위쪽 띠를 두지 말고 오른쪽 세로 레일(폭 144) 하나에 로고·운전 상태·알람·세로 트랙·시계·로그인을 담는다.
  콘텐츠는 1776x1080. IronHMI 영역은 NavRegion(레일) + ContentRegion.
- 프로그램 종료 버튼: 세로판은 로그인 버튼 옆, 가로판은 로그인 버튼 아래. 엔진의 action:HmiApplication.ExitOnClick을 쓰고, 정지 버튼과 헷갈리지 않게 빨간 글자 + 전원 아이콘 외곽선 버튼으로.
- 가로판 바깥 여백 12, 카드 간격 12.

세로판·가로판 각각의 틀 목업을 만들어 보여 주고, 내가 고르면 다음으로 넘어간다.
```

### 1-4. 작업현황 화면 배치

```text
작업현황(기본 화면) 배치를 정한다. 타일 문법 위에 아래를 넣어라.

- 운전 상태 타일 하나만 상태색으로 전체를 칠한다(운전 중 초록 · 일시정지 주황 · 알람 빨강 · 대기 회청). 나머지는 강철 파랑.
- 단계 타일 4개: ① 서보·원점 ② 프로그램(.cnc 불러옴) ③ 도포 중(진행 막대) ④ 완료(종료 예정 시각).
  완료 = 파랑 + 체크, 현재 = 밝은 타일 + 번호, 다음 = 회청.
- 3D는 지금보다 줄인다(세로판 약 688x562). 뷰 3종(토출/갠트리/라인)은 별도 타일로.
- 필수 정보: 프로그램 파일명(운전 중 잠금), 진행 %와 라인 n/N, 남은 시간(크게), 경과, 종료 예정.
- 축 X/Y/Z 타일(위치·속도·원점·알람), 머신 속도(피드 %), 토출 모드 [실제 토출 | 드라이런] 한 선택기(운전 중 잠금), 오늘 생산(작업이력 DB의 오늘 건수·완료/중단·평균 사이클).
- 보조: 수동조작 창, HOME, 대기 위치, 시뮬레이션 창.
- 늘 '–'만 보일 요소(리밋 칸, 공작물 좌표 등)는 넣지 마라. 압력 센서는 없다.
- 상태별 화면(대기·일시정지·알람)은 따로 그리지 않아도 된다. 운전 중 화면 하나로 보고.
```

## 2단계. 구현 계획

```text
1단계에서 확정한 디자인으로 IronHMI 프로젝트 구현 계획을 세워라. 계획만 가져오고, 내가 승인하면 작업한다.

[재사용]
- 참고·재사용 원본: <비슷한 장비의 기존 IronHMI 프로젝트 경로>.
  PLC 태그가 비슷하면 실제 diff로 확인하고 최대한 재사용해라.
- 3D: 기존 도포 트윈(링버퍼 실적 비드·지터버퍼 재생·구도 설정)을 가져와 이 장비용으로 고친다. 계획 경로는 .cnc 파일 해석 결과로 그린다.
- 트렌드 그래프: ScottPlot(DLL 안에 임베드). Helix는 3D 전용이다.

[구조]
- 컨트롤 팩 CncControls 소스는 src/HMI_Vertical/Controls/CncControls 한 곳에만 둔다.
  빌드 후 같은 DLL을 HMI_Vertical/Controls와 HMI_Horizontal/Controls 두 곳에 복사하고, DLL도 커밋한다.
- 구성설정처럼 반복이 많은 화면은 생성 스크립트(tools/make-config.ps1)로 만든다.
- 각 폴더: project.manifest.json, Frame.xaml, Screen/Layout, Screen/Panel, Config/(View3D·CncFolder·IOInfo), alarms.json, Models/
  Database/·Logs/는 .gitignore에 넣는다.

[PLC 연동]
- 운전 명령: gEquipment.Input.CncCommand (1 서보ON+원점 · 2 시작 · 3 일시정지 · 4 정지 · 5 리셋 · 6 재개 · 8 원점 복귀)
- 축: gAxis[0..2].Output.State.*, 3D 비드: ::RingBuffer:*
- 축 이동 범위: X −5…450, Y −5…395, Z −5…145 mm
- PLC가 막거나 값이 없는 것은 버튼을 배선하되 비활성 + 이유 표시:
  DI_Auto 하드코딩(IO\IO\Cyclic.st) → 조그·수동 토출·위치 이동이 막힘 / 압력 센서 없음 / 일시정지 상태 없음(HMI가 기억) /
  리밋 센서 미노출 / 지령 위치·공작물 좌표·블록 번호·서보 OFF 없음
- 안전: 조그는 누르는 동안만 움직이고, 떼거나 화면을 벗어나면 정지를 쓴다. 스텝 이동은 대기·정지 중일 때만. 축을 움직이는 명령은 확인 창을 거친다.
- 권한 등급(운전 10, 구성설정 편집 5 등)은 표로 제안만 하고 내가 확정한다.

[검증]
- dotnet build (경고 0·오류 0)
- ironhmi-cli check <폴더> --engine-root <IronHMI 설치 경로>\bin  (두 폴더 모두)
- ironhmi-cli render로 화면별 배치 확인
- render는 엔진 3D(뷰 큐브·카메라 버튼)를 그리지 않으니, 3D 위 겹침은 IronHMI 실행 캡처로 확인한다.
- 개발 PC 배율이 100 %가 아니면 창이 잘리는 점을 감안한다.

계획에 결정이 필요한 것(해상도, 범위, 라이브러리 등)이 있으면 계획 전에 질문으로 먼저 물어라.
```

> 이 프롬프트를 쓸 때(2026-10)의 PLC 상태가 적혀 있습니다. 지금 PLC는 `DI_Auto`를 HMI의 수동/자동 선택으로 받고, 일시정지·서보 OFF·리밋 센서 값도 내놓습니다(`CLAUDE.md` 참고).

## 3단계. 작업

### 3-1. 세로판 구현

```text
승인한 계획대로 src/HMI_Vertical을 만든다. 작업 브랜치 feature/hmi-initial에서 진행한다.

순서: 골격 → 컨트롤 팩 골격 → 작업현황 배치 → 3D → 트렌드 → 떠 있는 창(수동조작·시뮬레이션·트렌드 상세) → 나머지 4화면 → 알람
- 단계마다 빌드 → check → render로 목업과 비교한 뒤 [초안] 커밋한다.
- 목업과 다르게 둔 곳(PLC에 값이 없어서 등)은 커밋 메시지와 최종 보고에 적어라.
- 끝나면 IronHMI로 실행해서 로드·OPC UA 구독·알람 감시가 시작되는지 로그로 확인한다(PLC 미연결 상태).
```

### 3-2. 가로판 구현

```text
src/HMI_Horizontal에 가로판(1920x1080)을 만든다.
- 태그·컨트롤·설정·알람·3D 모델은 세로판과 같고 배치만 다르다. 컨트롤 소스를 복제하지 마라.
- 화면 틀은 1-3에서 정한 우측 레일(NavRegion 1776,0 144x1080 + ContentRegion 0,0 1776x1080), 바깥 여백 12, 간격 12.
- 작업현황: 왼쪽 3D(최대한 크게), 오른쪽 칸에 축·트렌드·보조·운전 명령. 늘어난 공간은 3D와 목록에 먼저 준다.
- 가로판에 필요한 컨트롤 속성(섹션 열 수, 트렌드 시트 방향 등)은 세로판 기본값을 바꾸지 않는 선에서 추가한다.
- 끝나면 두 폴더 모두 check를 통과하고, DLL 두 개가 같은지 확인한다.
```

### 3-3. 검토·수정 요청할 때 쓰는 형식

```text
[대상] 세로판/가로판 · 화면 이름
[문제] 실제 화면에서 본 것 (캡처 첨부)
[원하는 방향] 예: "여백 줄이기", "벤치마크에 더 가깝게"
[범위] 다른 화면·다른 판에 영향을 줘도 되는지
[산출] 목업으로 먼저 / 바로 반영
```
